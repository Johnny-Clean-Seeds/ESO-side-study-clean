# Chat Drop Copy — Rainbow Road Entry Rule V1

Date: 2026-05-27  
Status: CHAT DROP COPY / SUIT RULE CANDIDATE / GATE-ENTRY CONTROL  
Authority: not doctrine, not ACTIVE_GUIDES, not CURRENT_TRUTH_INDEX  
Purpose: prevent gate/tool/code changes from judging themselves by one gate alone.

## Core rule

Gate code should never run itself as its own whole authority.

Code Gate may be the start gate for code syntax and run safety.

Code Gate is not the whole rainbow road.

Anything that is trying to enter the house must go down the rainbow road before it is treated as installed, adopted, promoted, or house-safe.

This includes:

- ideas;
- concepts;
- rules;
- helper scripts;
- Code Gate runner changes;
- tool changes;
- cockpit behavior changes;
- suit cards;
- workbench changes;
- mule handoffs;
- save packets;
- proof claims.

## Rainbow road

Minimum road:

1. Front Door selects the object.
2. Alpha locks object, source, mode, lane, boundary, and proof need.
3. Router sends it to the right room/rule family.
4. Relevant gates judge it.
5. Evidence/proof is collected.
6. Fit decision is made: adopt, adapt, park, block, proof, leave-be.
7. Neighbor/boundary effects are checked.
8. Final Judge/Omega closes the run.
9. Only then can it be saved, installed, promoted, or worn.

## Code Gate's place

Code Gate is a necessary gate for PowerShell/helper scripts.

It can say:

- parser passed;
- parser failed;
- blockers found;
- warnings found;
- target ran;
- target failed;
- PASS WITH WATCH.

It cannot say by itself:

- this is now house doctrine;
- this is installed;
- this is promoted;
- this should replace the current gate;
- this is fully safe across all lanes;
- this belongs in ACTIVE_GUIDES or CURRENT_TRUTH_INDEX.

## Current example

`POWERSHELL_CODE_GATE_RUNNER_V1.4_CANDIDATE.ps1` passed as a candidate wrapper.

It proved:

- V1.3 still owns parser/run verdict;
- V1.4 candidate can read the V1.3 report;
- V1.4 candidate prints warning titles/counts;
- V1.4 candidate does not modify Code Gate.

It did not prove:

- install V1.4;
- replace V1.3;
- change Code Gate policy;
- promote warning judgment to doctrine.

Next road after candidate proof:

1. Review candidate proof.
2. Run it through warning judgment evidence.
3. Run fit/boundary/neighbor check.
4. Decide install candidate or park.
5. If install, make a narrow install/update script with receipt.
6. Re-test after install.
7. Only then update status.

## Few exceptions

Exceptions are few and bounded.

Direct answer exception:
- A simple chat answer does not need a full file/gate/save route.

Read-only inspection exception:
- Exact read-only inspection can proceed when it does not move, save, install, delete, or promote.

Emergency path repair exception:
- If a path/download/launcher error blocks proof, a tiny path repair may happen first.
- The repair must not become promotion.

Local housekeeping exception:
- Moving already-installed drop-copies out of root can happen as local housekeeping.
- It still needs receipt and no delete.

None of these exceptions allow doctrine promotion, active-guide rewrite, current-truth rewrite, hidden tool replacement, or proof skipping.
