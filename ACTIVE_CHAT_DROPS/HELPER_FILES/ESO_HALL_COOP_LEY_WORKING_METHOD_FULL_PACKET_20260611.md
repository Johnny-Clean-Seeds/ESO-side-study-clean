## 0. Core operating sentence

The method is: lock the object, separate source lanes, let clues breathe without calling them proof, test the structure, pressure the weak points, close each run with explicit status, and carry unresolved material in Soft Suit until proof decides.

The working purpose is: find the source truth without letting attractive symbols, weak internet trails, bad captions, visual similarity, or pattern hunger take control.

The four core laws are:

1. Lock the object first.
2. Separate source lanes.
3. Let suspicion breathe without calling it proof.
4. Close each run with what changed, what cracked, what stayed open, and what comes next.

## 3. Mode system

Each answer or run should declare the mode at the top.

### RESEARCH RUN

Used when actively searching, testing, source-locking, or analyzing the next target.

Required shape:

- Mode line.
- Run line.
- State line.
- Findings.
- What locks.
- What cracks or stays bounded.
- Soft Suit update.
- Current conclusion.
- Next run.

### FLOORS / CLOSEOUT

Used after a section or batch has enough material to judge.

Purpose: decide what survives, downgrades, parks, blocks, enters index, or moves next.

Floors does not start a fresh wide research pass. It walks the floor and classifies the load.

### BRIDGE

Used when two lanes may connect but cannot merge yet.

Bridge says:

- this may connect;
- here is the possible shared mechanism;
- here is why we do not merge;
- here is the allowed next run.

Used for Hall/Grove orientation and mule split decisions.

### FREEZE

Used when the user says “hold the rope” or when state must be preserved before movement.

Freeze does not start new research. It preserves:

- current branch;
- active object;
- last locked result;
- next planned run;
- live Soft Suit carry;
- blocked claims;
- parked lanes.

### METHOD DROP

Used to explain the operating system itself.

No new claims should be introduced unless clearly marked as method rather than research.

### HOLDINGS DROP

Used to dump current Soft Suit carry, locks, holds, watches, blocked claims, and next plan.

### HARD-CONTROL RUN

Used when an attractive claim needs official/source pressure.

Examples: Great Seal official history, Franklin Masonic record, Columbus green-cross banner, Americke naming theory.

### VISUAL SOURCE HUNT

Used when a picture, frame, caption, plate, artifact, manuscript page, or source image needs custody.

Rule: image clue is not proof until source route, object label, timestamp/order, visible content, and claim boundary are logged.

## 5. 33rd Triple Pass

The deep-run method is:

`Walls -> Ceiling -> Roof -> Floors / Closeout`

The older wording “Whole-House Floor Run” means the final floor walk, not a new giant research pass. The corrected term is Floors / Closeout / Conclusion Run.

### Walls

Walls means the visible body.

Collect:

- names;
- titles;
- visible images;
- exact phrases;
- places;
- dates;
- captions;
- source names;
- artifacts;
- obvious claims;
- obvious conflicts.

Walls answers: what is on the table?

Walls does not decide meaning.

### Ceiling

Ceiling means the load-bearing structure.

Ask:

- What source supports this?
- What came before what?
- What depends on what?
- Is this primary source, later interpretation, museum object, or generic web?
- Is the map single-source or composite?
- Is the image from Hall, Mercy, a museum, an old plate, or modern illustration?
- Does the timeline hold?

Ceiling answers: what is carrying the claim?

### Roof

Roof means outside pressure.

Ask:

- What could be false?
- What source is weak?
- What are we overreading?
- What evidence should exist if this were true?
- Is this only visual similarity?
- Are official history and Hall interpretation getting mixed?
- Are we turning a clue into proof?
- Are we flattening several Indigenous traditions into one system?
- Is this Facebook caption, museum object, page image, or primary source?

Roof answers: what can break this?

### Floors / Closeout

Floors decides what survives.

It says:

- this enters the index;
- this stays in Soft Suit;
- this downgrades;
- this is blocked;
- this needs transcript;
- this needs image-source lock;
- this becomes next run.

Floors answers: what do we carry forward, and at what proof weight?

## 9. Rule cards

Rule cards are reusable control laws.

### MARKER-OBJECT-LOCK

Before meaning, lock the object.

Fields:

- location;
- exact visible words;
- dates;
- symbols;
- material if known;
- placement;
- maker;
- institution;
- first documented appearance;
- current photo/source;
- source quality.

### COVER-MARKER-RIDDLE-SPLIT

Every object gets four readings:

- cover reading: official/common explanation;
- marker reading: what the object does in place;
- riddle/code pressure: contradiction, wordplay, date pattern, symbol tension, repeated motif;
- proof status: proven, likely, possible, unsupported.

Official meaning is allowed, but not allowed to eat the whole object.

### KNOWN-LOCATION-INDEX-FIRST

No deep dive before the object/location is placed in the master index.

### DATE-HANDLING

Each date gets:

- documented event;
- placement function;
- pattern pressure.

### SOURCE-LADDER-TRIANGULATION

Use multiple source families for important claims.

Preferred route:

- primary/object;
- institutional/archive;
- museum/scholarly;
- official civic history;
- named interpretive source;
- media transmission;
- generic web;
- social/unsourced material.

### NAME-VARIANT-STORM

Search alternate names, spellings, transliterations, OCR errors, clipped captions, source titles, and role words.

Examples:

- Itzamna / Itzama / Zamna / God D;

### PLACE-CHAIN-RECONSTRUCTION

Build movement/layer chains, not isolated dots.

Examples:

- Hall chain: Mesoamerican source -> North American initiation -> European transmission -> American national symbols.

### MAP-GRID-EXTRACTION

Turn maps into tables.

Fields:

- base map;
- icon type;
- marker color;
- label;
- road/trail;
- region;
- legend;
- source/platform;
- overlay;
- editorial elements;
- exact source status.

### CONTRADICTION-HARVEST

Preserve conflicts instead of smoothing them away.

Examples:

- April 9 vs May 17 incorporation dates;
- Hall’s “banner of his own” vs expeditionary green-cross banner control;
- Americke naming theory vs Waldseemüller/Vespucci control;
- Hall’s Nathaniel Bacon genealogy vs modern genealogy controls.

### NEGATIVE-SPACE-SEARCH

Ask what evidence should exist if the claim were true.

Examples:

- If Columbus banner were clearly Templar, strong primary/institutional evidence should appear.
- If Kittel/RAMADDA were the full Mercy map, it should explain Mexico/Yucatán.
- If Ephrata were a formal Rosicrucian lodge, charter/order evidence should appear.

### ADJACENT-QUARANTINE

Nearby material can compare, but cannot steer without source linkage.

Examples:

- Masonic symbolism can compare with Parker/Red Hand, but cannot prove Native societies were Freemasonry.
- Grove ritual grammar can compare with Hall’s lodge/fire/death/light grammar, but cannot prove Grove is in the Hall chain.

### PROOF-STATUS-DOWNGRADE

No row stays overpromoted.

When control weakens a claim, downgrade the row.

Examples:

- Kittel/RAMADDA: possible full map source -> U.S.-layer candidate only.
- Newport 1658: possible early Masonry -> disputed tradition / do not promote.
- Columbus Templar banner: high-value symbol clue -> Hall speculation only.

### BATCH-CLOSEOUT

End each batch with:

- new nodes;
- upgrades;
- downgrades;
- false leads;
- gaps;
- blocked claims;
- Soft Suit updates;
- next target.

## 10. Proof labels

Use explicit labels.

`LOCKED_OBJECT` — exact thing exists and is supported.

`LOCKED_SOURCE` — source exists; specific claim inside may still need extraction.

`CONFIRMED_OBJECT` — object/place documented, interpretation not necessarily proven.

`CONFIRMED_FAMILY` — type/family exists, exact object may be open.

`STRONG_NODE` — good support, not final.

`LIKELY_NODE` — plausible and supported, incomplete.

`CANDIDATE_NODE` — possible, needs proof.

`WATCH` — do not merge, do not drop.

`ADJACENT_ONLY` — useful comparison, not same lane.

`REJECTED_FALSE_LEAD_UNTIL_REPROVEN` — bad lane unless new evidence reopens it.

`BLOCKED` — do not say as fact.

`QUARANTINED` — keep from steering because too unstable or attractive.

3. Museum, university, scholarly site/report.
4. Official civic/design history for civic claims.
5. Named interpretive source for that source’s own interpretation only.
6. Video/audio transmission for sequence and editing only.
7. Generic web material.
8. Social media, unsourced symbolic comparisons, sacred-geometry material.

- Hall is strong for Hall’s interpretation.
- Hall alone is weak for archaeology.
- Mercy is strong for what Mercy shows and how the edit behaves.
- Mercy alone is weak for source proof.

- video/part number;
- timestamp;

- on-screen text;

`NEW_SOURCE_TARGET` — new clue worth researching.

## 22. Source custody and DoesNotProve discipline

Custody proof is not claim proof.

A file receipt, archive extraction, copied folder, source list, or restored folder proves only what it directly proves:

- that a file exists;
- that it was copied;
- that an archive route exists;
- that a source object was identified;
- that a scan or catalog record is available.

It does not prove:

- research claim correctness;
- source completeness;
- publication readiness;
- symbolic interpretation;
- historical lineage.

This matters for ESO source archive, mule transcript dumps, image folders, map screenshots, and archive/source packs.
