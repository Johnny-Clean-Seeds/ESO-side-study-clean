# Smart Mirror Signal Governance Anchor V0.1

Status: ACTIVE_ANCHOR / SMART_MIRROR_SIGNAL_GOVERNANCE / NOT_DOCTRINE / NOT_EXECUTION_AUTHORITY  
Date: 2026-06-16  
Scope: Mirror chatter gate, cross-chat signal quality, active-lane contamination prevention.

## Purpose

This anchor preserves the current mirror-governance decision.

Mirrors are not bad by default. Some mirror chatter improves work across chats by carrying useful patterns, rules, and method corrections better than Git alone.

The problem is not mirror existence.

The problem is raw mirror chatter entering the wrong lane, especially execution lanes, without judging whether the signal is current, aligned, helpful, stale, harmful, growth, or bloat.

## Core Rule

A mirror is not useful because it has something to say.

A mirror is useful only when its signal improves the current job.

Presence is not permission.  
Path visibility is not permission.  
Old helper history is not permission.  
Mirror chatter is not authority.

## Required Mirror Questions

Before mirror signal enters active work, it must answer:

1. Does this align with the current task or job?
2. Is this current, stale, superseded, proof-only, or unknown?
3. Does this reinforce the active work or hinder it?
4. Is this growth or bloat?
5. What does this help?
6. What does this risk?
7. Where does it belong: ADOPT, ADAPT, PARK, BLOCK, PROOF, or LEAVE-BE?
8. What is the smallest safe return form?

## Good Mirror Signal

A good mirror signal:

- clarifies the active task;
- catches hidden drift;
- names stale carry;
- reduces repeated failure;
- separates idea work from execution work;
- improves the next move;
- compresses old learning into current usable language;
- returns as a small rule, card, dry check, proof pointer, or next action.

## Bad Mirror Signal

A bad mirror signal:

- leaks stale tone;
- carries old helper voice into current work;
- adds rank/deference language;
- adds roleplay or persona;
- revives old anchors without promotion;
- opens side lanes;
- makes agents load more than needed;
- treats archive/history as live authority;
- returns broad chatter instead of distilled value.

## Lane Rule

1step2step is the idea/design lane. Mirrors may speak more broadly there when the job is concept design, method design, system improvement, or cross-chat pattern work.

ESO is the execution/local-file lane. Mirrors are quiet by default there. ESO receives only distilled mirror output: a current rule, helper card, receipt, dry check, proof pointer, or one next action.

## Blocked

Do not import old tone, persona, rank language, deference language, roleplay, obsolete helper phrasing, or unclassified archive chatter into active execution.

The word “boss” is blocked as partner-tone contamination except when quoted as a diagnosed failure term.

## DoesNotProve

This anchor proves only the current mirror-governance decision. It does not prove the mirror system is fully designed, implemented, tested, active doctrine, safe for automation, or approved for broad cleanup.
